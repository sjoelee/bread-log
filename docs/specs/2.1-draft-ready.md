# Spec 2.1 — Draft / Ready

Behavior for slice 2.1. Decisions and their reasons are in ADRs 0007, 0011, 0013, 0014
and 0015; this file says exactly what the system does. Terms are in
[`../glossary.md`](../glossary.md). Review this before implementation starts; items under
**Open** are not decided.

## Summary

A recipe has recipe-level details (name, category, notes) and versioned content
(ingredients, steps). Content lives in at most one Draft and any number of Ready versions.
Saving changes the Draft; promoting freezes it into the next numbered Ready version;
discarding throws it away.

## Rules

| # | Rule | Source |
|---|---|---|
| R1 | A recipe has 0 or 1 Draft and 0 or more Ready versions, never neither. | 0007, 0011 |
| R2 | Name, category and notes are edited directly on the recipe, take effect immediately, and are not versioned. Names need not be unique. | 0013 |
| R3 | Creating a recipe creates it with a Draft and no Ready version. | 0007 |
| R4 | Saving content replaces the Draft's ingredients and steps. If the recipe has no Draft, saving creates one. No version number is assigned. | 0007 |
| R5 | Promoting requires a Draft. It is rejected if the recipe has no Draft. | 0015 |
| R6 | Promoting is rejected if the Draft's content equals the latest Ready version's ("equal" = no ingredient or step added, removed, modified or reordered). A recipe with no Ready version can always promote. | 0015 |
| R7 | Promoting assigns `latest Ready number + 1` (1 if none), records the optional release note and the change summary against the previous Ready version, makes it the latest Ready version, and leaves the recipe with no Draft. | 0007, 0015 |
| R8 | Ready versions are never modified. | 0007 |
| R9 | Discarding the Draft of a recipe that has a Ready version removes the Draft; the Ready versions are unchanged. | 0014 |
| R10 | Discarding the Draft of a recipe with no Ready version deletes the recipe. | 0014 |
| R11 | Deleting a recipe removes it, its Draft and all its Ready versions. | 0014 |
| R12 | History lists Ready versions only. | 0007 |

## Use cases (application layer)

| Use case | Input | Result | Errors |
|---|---|---|---|
| `create_recipe` | name, category?, notes?, ingredients, steps | recipe with a Draft (R3) | — |
| `update_details` | recipe id, name, category?, notes? | recipe (R2) | not found |
| `save_draft` | recipe id, ingredients, steps | recipe with the saved Draft (R4) | not found |
| `promote` | recipe id, release note? | recipe with the new latest Ready version, no Draft (R7) | not found; no Draft (R5); unchanged (R6) |
| `discard_draft` | recipe id | recipe without a Draft (R9), or recipe deleted (R10) | not found; no Draft |
| `delete_recipe` | recipe id | — (R11) | not found |
| `get_recipe` | recipe id | recipe with `latest_ready` and `draft` | not found |
| `list_recipes` | filters (below) | summaries | — |
| `get_versions` | recipe id | Ready versions, newest first (R12) | not found |
| `get_version_diff` | recipe id, two version ids (either may be the Draft) | diff | not found |

The domain owns R1 and R4–R10: `Recipe.save_draft`, `Recipe.promote`, `Recipe.discard_draft`
and `Recipe.update_details` enforce them. `Recipe.add_version()` is removed.

## API

| Method and path | Use case | Success | Errors |
|---|---|---|---|
| `POST /recipes/` | `create_recipe` | 201, Recipe | 422 invalid input |
| `PATCH /recipes/{id}` | `update_details` (name, category, notes only) | 200, Recipe | 404, 422 |
| `PUT /recipes/{id}/draft` | `save_draft` (ingredients, steps) | 200, Recipe | 404, 422 |
| `POST /recipes/{id}/promote` | `promote`, body `{release_note?}` | 200, Recipe | 404; 422 no Draft or unchanged |
| `DELETE /recipes/{id}/draft` | `discard_draft` | see Open O2 | 404; 422 no Draft |
| `DELETE /recipes/{id}` | `delete_recipe` | 204 | 404 |
| `GET /recipes/{id}` | `get_recipe` | 200, Recipe | 404 |
| `GET /recipes/` | `list_recipes` | 200, list of RecipeListItem | 422 |
| `GET /recipes/{id}/versions` | `get_versions` | 200, list of RecipeVersion | 404 |
| `GET /recipes/{id}/versions/{v1}/diff/{v2}` | `get_version_diff` | 200, diff | 404 |

Removed: `POST /recipes/{id}/versions` (replaced by save + promote). `PATCH /recipes/{id}`
no longer accepts ingredients or steps.

**Recipe** (response): `id`, `name`, `category`, `notes`, `created_at`, `updated_at`,
`latest_ready` (RecipeVersion, optional), `draft` (RecipeVersion, optional). At least one
of `latest_ready` / `draft` is present (R1). No single "current version" field (ADR 0011).

**RecipeVersion**: `id`, `state` (`draft` | `ready`), `version_number` (null for the
Draft), `release_note` (null for the Draft), `ingredients`, `steps`, `change_summary`
(null for the Draft), `created_at`.

**RecipeListItem**: `id`, `name`, `category`, `notes`, `created_at`, `updated_at`,
`latest_ready` (optional summary), `draft` (optional summary). A summary is `version_id`,
`version_number` (null for the Draft), `ingredient_count`, `step_count`.

**List filters**: the existing `search`, `ingredient`, `category`, `sort_by`,
`sort_direction`, `limit`, `offset`, plus `state` = `any` (default) | `draft` | `ready`.
Content filters (`ingredient`, and `search` where it matches content) match:

- `draft`: the Draft only; recipes without a Draft are excluded.
- `ready`: the latest Ready version only; recipes without one are excluded. Older Ready
  versions never match.
- `any`: the Draft or the latest Ready version.

## Data

- The schema already supports this (`state`, nullable `version_number`, the
  draft/number check constraint, and the one-Draft-per-recipe unique index are in
  `database/schema.sql`). `recipes.current_version_id` points at the latest Ready version
  and is null for a recipe with none.
- Recipe-level fields stay on `recipes`: `name`, `category`, and `description` (holds
  notes). The version's `description` holds the release note.
- Existing dev data is test data and is wiped; no migration of existing rows.

## Acceptance scenarios

1. Create "Country Sourdough" → `draft` present, `latest_ready` absent; not in
   `GET /recipes/?state=ready`.
2. Save the Draft twice → still one Draft, no version number, history empty.
3. Promote with no note → v1; `draft` absent; history = [v1]; `release_note` null.
4. Promote again with no Draft → 422; nothing changes.
5. Save a Draft identical to v1 → promote → 422 (R6).
6. Save a changed Draft → promote "more water" → v2; v1 unchanged; history = [v2, v1];
   v2's change summary is against v1.
7. Rename the recipe and change its notes with a Draft present → takes effect at once;
   the Draft and v1/v2 are untouched.
8. Save a Draft on a recipe with v2 → discard → `draft` absent, history unchanged.
9. Create a recipe, discard its Draft → the recipe no longer exists (404).
10. Delete a recipe with v1, v2 and a Draft → 204; all rows gone.
11. Two recipes named "Tangzhong" can both exist.
12. Diff the Draft against v2 → returns the diff.
13. A recipe with v1 (contains rye) and a Draft (rye removed):
    `?ingredient=rye` matches; `?ingredient=rye&state=draft` does not;
    `?ingredient=rye&state=ready` does.

## Open

- **O1** How a client learns whether the Draft differs from the latest Ready version (to
  disable Promote). Deferred.
- **O2** Response of `DELETE /recipes/{id}/draft`: proposal is 200 with the Recipe when it
  still exists and 204 when the recipe was deleted (R10).
- **O3** The API keeps the field name `description` for notes, or renames it to `notes`.
  This spec uses `notes`.
- **O4** The current frontend reads `current_version` and calls the removed endpoints, so it
  breaks when 2.1 ships until Phase 3 updates it. Accept that, keep compatibility fields
  during 2.1, or make a minimal frontend fix in 2.1.
- **O5** The Draft has no "last saved" time; `created_at` is when it was started. Add an
  `updated_at` to versions, or leave it.
